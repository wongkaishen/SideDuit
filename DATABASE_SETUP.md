# Database Setup Guide for SideDuit

## Architecture Overview

SideDuit uses **TWO databases**:

### 1. Django SQLite (Local) - For Django Admin
- **Models**: `Income`, `Expense`
- **Purpose**: Optional local tracking via Django admin
- **Location**: `db.sqlite3`

### 2. Supabase PostgreSQL (Cloud) - For Production App
- **Tables**: `transactions`, `update_logs`
- **Purpose**: Main database for the app (OCR uploads, dashboard data)
- **Location**: Supabase cloud

---

## ⚠️ IMPORTANT: The Frontend Uses Supabase

The dashboard and analytics pages fetch data from **Supabase**, not the Django SQLite database.

## Supabase Database Setup

### Step 1: Create Tables in Supabase

Log into your Supabase project and run these SQL commands in the SQL Editor:

#### Create `transactions` table:

```sql
-- Table for all financial transactions
CREATE TABLE public.transactions (
  id bigint generated by default as identity primary key,
  year int,
  date date not null,
  time time without time zone,
  transaction_type text not null,
  transaction_amount numeric(10, 2) not null,
  document_id text,
  upload_id bigint,
  user_id text default '0',
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Create indexes for faster queries
CREATE INDEX idx_transactions_user_id ON public.transactions(user_id);
CREATE INDEX idx_transactions_type ON public.transactions(transaction_type);
CREATE INDEX idx_transactions_date ON public.transactions(date);
```

#### Create `update_logs` table:

```sql
-- Table to store upload logs and file content
CREATE TABLE public.update_logs (
  upload_id bigint generated by default as identity primary key,
  upload_user text,
  upload_document_name text,
  uploaded_document bytea,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Index for faster lookup by user
CREATE INDEX idx_update_logs_user ON public.update_logs(upload_user);
```

## Backend Environment Variables

Create a `.env` file in `backend/SideDuit/` directory:

```env
# Gemini API for OCR
GEMINI_API_KEY=your_gemini_api_key_here

# Supabase Database Connection
SUPABASE_DB_HOST=db.yourprojectref.supabase.co
SUPABASE_DB_NAME=postgres
SUPABASE_DB_USER=postgres
SUPABASE_DB_PASSWORD=your_supabase_db_password
SUPABASE_DB_PORT=5432
```

### How to Get Supabase Credentials:

1. Go to your Supabase project dashboard
2. Click on **Settings** (gear icon)
3. Go to **Database** section
4. Find **Connection String** → Choose "URI" format
5. Copy the values:
   - Host: `db.xxxxx.supabase.co`
   - Password: Click "Reset Database Password" if needed

## Troubleshooting

### "Not Found: /finance/api/dashboard-summary/"

✅ **FIXED** - The URL routes have been added. Restart Django server.

### "Database connection error" or "psycopg2 error"

Check:
1. ✅ Environment variables are correct in `.env` file
2. ✅ Supabase tables are created
3. ✅ Your IP is allowed in Supabase (Settings → Database → Connection Pooling)
4. ✅ Install dependencies: `pip install psycopg2-binary python-dotenv`

### "No data showing in dashboard"

Options:
1. ✅ Insert sample data (see SQL above)
2. ✅ Upload documents via `/upload` page
3. ✅ Check browser console for errors

### "GEMINI_API_KEY not set"

- Get free API key from: https://makersuite.google.com/app/apikey
- Add to `.env` file

## Summary

| Component | Database | Purpose |
|-----------|----------|---------|
| **Frontend Dashboard** | Supabase | Real-time financial data |
| **Upload/OCR** | Supabase | Store processed transactions |
| **Django Admin** | SQLite | Optional admin interface |

The main app flow:
1. User uploads receipt → Gemini AI extracts data
2. Data saved to **Supabase** `transactions` table
3. Frontend fetches from Django API → API queries **Supabase**
4. Dashboard displays real calculations
